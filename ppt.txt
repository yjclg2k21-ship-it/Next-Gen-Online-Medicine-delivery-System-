### Slide 2: Introduction
*   **The Concept**: MediMitra is a unified digital platform designed to bridge the gap between healthcare consumers and neighborhood pharmacies.
*   **Current Scenario**: Most local pharmacies in the Indian market still rely on manual billing and inventory, leading to errors and inefficiency.
*   **The Vision**: To create a "Clinical Pulse" where every medicine purchase is cross-verified for safety, and every inventory movement is tracked for efficiency.
*   **Platform Roles**: Integrated interfaces for Admin (Oversight), Vendor (Pharmacy), User (Patient), and Delivery Partner (Logistics).

---

### Slide 3: Abstract
*   **Aim**: This project addresses the lack of digital clinical oversight in localized pharmacy retail. 
*   **Methodology**: By utilizing a decoupled architecture (React + PHP), we provide a high-reactivity frontend for sales and a robust backend for safety checks.
*   **Innovation**: Implementation of a custom AI engine that parses drug compositions to detect lethal interactions before dispensing.
*   **Impact**: Enhances the reliability of local healthcare delivery and empowers small vendors with industrial-grade technology.

---

### Slide 4: Objective
*   **Primary Objective**: To automate the end-to-end pharmacy workflow from order placement to last-mile delivery.
*   **Safety Objective**: To minimize adverse drug reactions (ADRs) through a real-time AI-based Interaction Matrix.
*   **Operational Objective**: To provide vendors with forensic inventory tools like "Clinical Low stock" alerts and digital prescription review.
*   **Logistics Objective**: To create an automated dispatch queue that eliminates delays in medicine delivery.

---

### Slide 5: Literature Review
*   **State of Pharmacy Retail**: Analysis shows that while global e-commerce is rising, local pharmacies still handle 85% of retail but lack the software to manage clinical risks.
*   **Medication Error Statistics**: Research indicates that up to 20% of pharmacy errors are due to incorrect manual prescription reading.
*   **Consumer Trends**: Studies show that patients value "Clinical Safety" and accurate delivery tracking over simple pricing.
*   **Tech Gap**: Existing POS systems focus on "Billing" but ignore "Clinical Safety," which MediMitra solves.

---

### Slide 6: Problem Statement
*   **Inefficient Inventory Tracking**: Lead to stock-outs of critical life-saving drugs and losses due to expired medicine batches.
*   **Dangerous Drug Interactions**: Patients buying from multiple sources often consume conflicting medicines without safety warnings.
*   **Fragmented Logistics**: The absence of a unified delivery network for local pharmacies prevents them from competing with big-tech e-pharmacies.
*   **Data Silos**: Valuable medical data is lost in manual records, preventing the possibility of health trend analysis.

---

### Slide 7: Proposed Solution (The MediMitra Ecosystem)
*   **Consumer Portal**: Pure Web technology app for medicine search, clinical safety checks, and order tracking.
*   **Clinical Safety Gateway**: A PHP-driven layer that checks every order against a Contraindication Database.
*   **Vendor POS Interface**: A real-time dashboard for local pharmacies to manage sales, stock, and prescription vetting.
*   **Global Pulse Admin**: A high-level telemetry tool for monitoring system health and transaction transparency.

---

### Slide 8: System Architecture
*   **Architecture Pattern**: Decoupled N-Tier / Custom MVC.
*   **Layer 1 (Frontend)**: React 18, Vite (for performance), Framer Motion (for UI/UX fluidity).
*   **Layer 2 (API Layer)**: Secure JWT-authenticated RESTful endpoints in PHP.
*   **Layer 3 (Business Logic)**: DDI engine, Clinical Safety alerts, and Dispatch logic.
*   **Layer 4 (Database)**: MySQL 8.0 with optimized indexing for fast search and historical audit logging.

---

### Slide 9: Dataflow Diagram (DFD)
*   **Level 0 (External)**: User interacts with the UI -> API receives request -> MySQL returns data.
*   **Level 1 (Process)**:
    1.  **Selection Phase**: User adds items -> System triggers "AI Safety Check" in background.
    2.  **Validation Phase**: Vendor reviews prescription -> Approval updates "Order State".
    3.  **Logistics Phase**: Dispatch engine assigns "Delivery Partner" -> Real-time status sync.
    4.  **Accounting Phase**: MediWallet balance updated -> Transaction ledger recorded.

### Slide 11: Used Algorithms & Flowchart
*   **DDI Matrix Algorithm**: A Set-Theory based intersection check that compares ingredients in the new order against the user's active prescriptions.
*   **Inventory Forensic Logic**: A time-series analysis for predicting when a critical drug will reach "Low Stock" based on sales velocity.
*   **Forensic Telemetry**: An aggregation algorithm that builds the "Global Pulse" graph from live HTTP request metrics.
*   **Simplified Flowchart**:
    `START` -> `Login` -> `Medicine Search` -> `AI Constraint Engine` -> `Upload Prescription` -> `Vendor Approval` -> `Payment` -> `Dispatch` -> `Delivery` -> `END`.
